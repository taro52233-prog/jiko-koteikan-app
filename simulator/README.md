# 遺品整理 お見積りシミュレーター

サイト内にも、LINE（LIFF）内にも、同じファイルのまま設置できます。

```
simulator/
  index.html   アプリ本体
  pricing.js   料金テーブル・会社情報・事例   ← 運用中に編集するのはここだけ
```

## 設計の考え方

- **金額を当てにいかない。** 現地見積とのズレはクレームに直結するため、
  幅（レンジ）で示し、幅が出る理由も併記します。
- **物量を写真で聞く。** 「多い / 普通 / 少ない」では全員が「普通」を選ぶため、
  部屋のイラスト4段階から選ばせます。ここが金額を最も左右します。
- **「わからない」で必ず先へ進める。** 遠方にお住まいのご家族が
  実家の物量を把握していないケースが多いため。選ぶとレンジが広がります。
- **見積書を見た直後に、次の行動を取れるようにする。**
  予約のCTAは合計金額のすぐ下（20px）に置き、
  スクロールで見えなくなっている間だけ下部に追従バーを出します。
  お願いが安心材料より先に来るため、CTA自体に
  「無料・その場での契約なし・キャンセル無料」を持たせています。
- **金額は「お見積書」として出す。** 大きな数字を1つ出すのではなく、
  見積番号・作成日・有効期限・明細・前提条件のそろった書面の形にします。
  LINEでお送りするのも、この見積書です。
- **規模までは無条件で表示し、見積書をLINEでお届けする。**
  「続きを見るには友だち追加」という人質型ではなく、
  「お見積書をLINEでお送りします」という配達の形にしています
  （`gate.mode: 'line'`）。まず中身を確認したい間は `'none'` にしてください。
- **特殊清掃に該当したら、金額を出さずに個別相談へ分岐する。**
  金額が現場ごとに大きく異なり、数字を出すと双方が不幸になるためです。
  ご遺族に「室内で亡くなられてから時間が経っていますか」と正面から伺うのは
  酷なので、専用の設問は置かず、次の3か所で拾っています。
  いずれも `pricing.js` / `STEPS` の選択肢に `consult: true` を付けるだけで増やせます。

  | 拾う場所 | 選択肢 |
  |---|---|
  | 1問目 どのようなご状況ですか | まずは相談したい |
  | 3問目 お部屋の様子 | 足の踏み場がない |
  | 7問目 あわせてご希望のもの | においや汚れの除去（特殊清掃）／ 害虫の駆除 |

## 設置の手順

1. `pricing.js` の `company` を自社の情報に差し替える
2. `pricing.js` の `line.addFriendUrl` を自社の友だち追加URLにする
   （LINE Official Account Manager → 友だち追加ガイド）
3. `pricing.js` の `rates` を自社の実単価に差し替える **（重要）**
   初期値は業界の一般相場からの仮置きです。
4. `pricing.js` の `cases` を実績に差し替える
   アルゴリズムよりも実績のほうが信用されます。
5. `pricing.js` の `gate.mode` を決める
   - `'none'` … その場で見積書まで表示する（LINEへの遷移なし）
   - `'line'` … 見積書はLINEでお送りする
   `'line'` にした場合は `gate.demoUnlock` を **`false`** にしてください（公開前に必須）
6. `pricing.js` の `guarantee.enabled` を、上限をお約束できるかで決める

### LINE（LIFF）で使う場合

LINE Developers で LIFF アプリを作り、`pricing.js` の `line.liffId` に設定します。
設定すると、LINEアプリ内で開いたとき **すでに友だちの方は関門を自動で通過** し、
結果をトークに残せます。リッチメニューから LIFF URL を開く導線にしてください。

Webページ側からは「友だち追加が完了したか」を検知できないため、
サイト設置時は「追加したら押してください」の二段階になります。
きれいに繋ぐ場合は LINE Login チャネル＋サーバーが必要です。

## 計測

`track()` が GA4 / GTM（`dataLayer`・`gtag`）へ次のイベントを送ります。
どの質問で離脱しているか、関門の通過率がいくつかを必ず見てください。

| イベント | 意味 |
|---|---|
| `sim_start` | 開始 |
| `sim_answer` | 各質問への回答（どこで離脱したかが分かる） |
| `sim_hazard_branch` | 特殊清掃へ分岐 |
| `sim_result_scale_view` | 規模の表示（関門の手前まで到達） |
| `sim_gate_view` / `sim_gate_click` / `sim_unlock` | 関門の表示・押下・通過 |
| `sim_result_detail_view` | 金額の表示 |
| `sim_cta_reserve` / `sim_cta_tel` | 予約・電話。`at` で押された場所（`now` = 合計の直下 / `sticky` = 追従バー / `bottom` = 最下部）が分かります |
| `sim_share` | ご家族への共有 |

## 金額の計算について

`人件費 ＋ 処分費 ＋ 車両費` に希望時期の係数を掛け、追加のご希望を加算します。

作業人時と体制は次のように出しています。**いずれも実績に合わせた調整が前提の仮置きです。**

```
作業人時 = 荷物量(m³)
           × rates.hoursPerCbm        1m³あたりの人時
           × 階数の係数
           × 搬出経路の係数
           + 貴重品の捜索時間
           + (トラック2台目以降 × rates.hoursPerExtraTruck)

人数 = crew.staffByCbm（荷物量で決める）
       ＋ 搬出条件が厳しければ1名（crew.addStaffOnHardAccess）
       ※「わからない」と答えられた場合は増員しません

日数 = 作業人時 ÷（人数 × crew.hoursPerStaffPerDay）
       0.5日単位に丸め、半端が出たら「1〜2日」と幅で表示
```

幅は、条件ごとの幅を**二乗和平方根で合成**しています。
「物量」「階数」「搬出経路」がすべて同時に最悪側へ振れることは現実には起きないため、
単純に掛け合わせると幅が非現実的に広がってしまうためです。
結果として、回答が揃っているときは中心値から **±12〜16%** 程度に収まり、
「わからない」が増えるほど幅が広がります。

なお車両は `rates.truckName` / `cbmPerTruck` / `truckPerUnit` で定義しており、
初期値は **3tトラック・10m³・1台24,000〜28,000円** です。
画面の表記もここから引いているため、2t基準に戻す場合もこの3項目だけで済みます。

## 動作確認

```
cd simulator && python3 -m http.server 8777
# http://127.0.0.1:8777/index.html
```

`pricing.js` を `<script src>` で読み込むため、`file://` ではなく
HTTP で開いてください。
