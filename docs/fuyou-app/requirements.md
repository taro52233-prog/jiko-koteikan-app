# 扶養ライン判定アプリ 要件定義書（初版 v0.1）

- 作成日: 2026-11-01
- 状態: 壁打ち用ドラフト（専門家監修前。本書の金額・条件はすべて「要一次資料確認」）
- 仮称: 未定

---

## 1. 目的

扶養内で働く人が「今年、どの壁を、いつ、あと何円・何時間で超えるか」を、
根拠つきで、すぐに把握できるようにする。

最終的な収益源は、小規模事業所（歯科医院など）向けの有料版とする。
個人版は無料で提供し、利用者獲得と計算の正しさの検証の場とする。

## 2. 方針（決定事項）

| 項目 | 決定 |
|---|---|
| 開発順序 | 個人版（無料中心）→ 個人プレミアム → 事業所版（主な課金） |
| 対象者の個別化 | 質問に答えると、その人の条件に合った判定だけが出る形にする |
| 提供形態 | Webアプリ（PWA）から始める。後でスマホアプリにできる構成にする |
| デザイン | シンプルで洗練された見た目。AIが作ったとわかる表現は使わない（§9） |
| 監修 | 現在はいない。リリース前に社労士・税理士の監修を受けることを必須条件にする |

## 3. 法的な位置づけと正しさを守る仕組み

### 3.1 前提
- 社会保険の扶養を認めるかどうかを決めるのは、扶養する側の加入保険者（健保組合・協会けんぽ・共済）。アプリは判定を代行しない。
- 税理士法により、個別の税務相談は無料でも税理士にしかできない。アプリは「一般的な計算ツール」の範囲にとどめ、個別の助言（チャットでの相談など）は行わない。
- 社労士法により、手続き書類の作成・提出代行は行わない。

### 3.2 正しさを守る仕組み（必須要件）
1. **ルールのデータ化**: 壁の金額・条件をプログラムに直接書かず、施行日ごとのルール表（JSON）として持つ。各ルールに、出典URL・施行日・最終確認日・監修者を記録する。
2. **根拠の表示**: 判定結果ごとに根拠（出典）と最終確認日を表示する。
3. **確度の3段階**: 「確定」「見込み」「保険者・勤務先に確認が必要」。
4. **安全側の計算**: 未回答の項目や不明な項目は、扶養から外れる側で計算する。
5. **テスト**: 公式資料の計算例をテストケースにし、ルール変更のたびに全件を自動で検証する。
6. **法改正への対応**: 年1回（12月の税制改正大綱、4月・10月の社会保険の施行時期）にルールの見直しを行う。
7. **利用規約・免責**: 「シミュレーションであり、最終判断は保険者・税務署・勤務先が行う」ことを明記する。有料版を出す前に賠償責任保険を検討する。

## 4. 判定する壁の一覧（2026年11月時点の調査。すべて要一次資料確認）

> 注: 2025年分・2026年分で大きな改正が続いている。以下は二次情報を含む調査結果であり、
> 監修時に国税庁・厚労省・日本年金機構の一次資料で確認する。

### 4.1 税金（本人側）
| 壁 | 2026・2027年分の目安 | 備考 |
|---|---|---|
| 所得税がかかり始める | 給与収入 178万円 | 基礎控除104万円（本則62万＋特例42万）＋給与所得控除の最低保障74万円。2028年分以降は現行法で168万円になる見込み |
| 住民税がかかり始める | 自治体ごとに異なる | 令和8年度（2025年所得）分は旧基準。2026年所得分の扱いは要確認 |

### 4.2 税金（扶養する側＝夫などの控除）
| 壁 | 2026・2027年分の目安 | 備考 |
|---|---|---|
| 配偶者控除 | 配偶者の給与収入 136万円以下（合計所得62万円以下） | 2025年分は123万円以下 |
| 配偶者特別控除（満額） | 〜169万円 | 扶養する側の合計所得900万円以下の場合 |
| 配偶者特別控除（ゼロになる） | 207万円超 | 段階的に減る |
| 扶養する側の所得制限 | 合計所得1,000万円超で配偶者控除なし | |

### 4.3 社会保険（扶養から外れる）
| 壁 | 条件 | 備考 |
|---|---|---|
| 健康保険の被扶養者・国民年金第3号 | 年間収入130万円未満（60歳以上・一定の障害者は180万円） | 通勤手当を含む。同じ世帯なら扶養する側の収入の2分の1未満も条件 |
| 19〜23歳の特例 | 150万円未満 | 2025年10月から。配偶者は対象外 |
| 判定方法の変更 | 2026年4月から、労働条件通知書などの契約内容で年間収入を判定 | シフト制で時間が決まっていない場合や契約期間1年未満の場合は従来どおり実績で判定。一時的な残業で超えても、すぐ扶養から外れるとは限らない |
| 扶養する側が国民健康保険 | 健康保険の「扶養」という仕組みがない | 自営業の世帯などが該当。質問で最初に分ける |

### 4.4 社会保険（勤務先で加入義務が生じる）
| 壁 | 条件 | 備考 |
|---|---|---|
| 短時間労働者の加入 | 週20時間以上、学生でない、勤務先が企業規模要件を満たす | 月8.8万円（106万円）の賃金要件は2026年10月に撤廃予定（施行の確定を要確認） |
| 企業規模要件の段階的縮小 | 51人以上 → 2027年10月 36人以上 → 2029年10月 21人以上 → 2032年10月 11人以上 → 2035年10月 撤廃 | |
| 4分の3基準 | 所定労働時間・日数が正社員の4分の3以上 | 規模に関係なく、すべての適用事業所。小規模な歯科医院ではここが実際の分かれ目になることが多い |
| 勤務先が適用事業所か | 法人は強制適用。個人事業は業種と人数による | 個人開業の歯科医院では、スタッフが歯科医師国保に入っている場合がある |
| 雇用保険 | 週20時間以上 | 2028年10月から週10時間以上に拡大予定 |

### 4.5 勤務先の制度（扶養する側の会社）
| 壁 | 条件 |
|---|---|
| 配偶者手当・家族手当 | 会社ごとに異なる（103万・130万などが多い）。利用者が入力する |

## 5. 対象者の個別化（質問の流れ）

質問に答えるごとに、関係する壁だけが残る仕組みにする。1画面1問、全体で3〜5分以内を目標とする。

1. **扶養される人は誰か**: 配偶者／子ども（学生）／親 ※MVPは配偶者のみ。学生は次の版で対応する
2. **年齢**: 60歳以上か、19〜23歳か
3. **扶養する側の健康保険**: 協会けんぽ／健保組合／共済／国民健康保険／わからない
   - 国民健康保険なら、§4.3の社会保険の扶養の判定はしない
   - 「わからない」なら、保険証の見方を案内する
4. **扶養する側の年収（目安）**: 配偶者控除の所得制限と、収入の2分の1要件の判定に使う
5. **扶養する側の会社の配偶者手当**: ある／ない／わからない。ある場合は条件の金額を入力する
6. **本人の勤務先**: 法人／個人事業、厚生年金に入っている人数（51人以上か、36人以上か…）、わからない
7. **働き方の契約**: 時給、週の所定労働時間、所定労働日数、契約期間、シフト制か、正社員の所定労働時間
8. **手当**: 通勤手当（月額）、賞与の有無
9. **学生か**
10. **掛け持ちの有無**: ありなら勤務先ごとに入力する
11. **今年すでに受け取った給与**: 月ごと、または合計

**結果の出し方**: 壁ごとにカードを出す。各カードに次を表示する。
- 判定（超えない／超える見込み／確認が必要）と確度
- あと何円、あと何時間（今の時給で計算）
- 判断の基準になるもの（1〜12月の実績か、契約内容か）
- 根拠と最終確認日

## 6. 機能一覧

### 6.1 個人版・無料（MVP）
- 質問による個別判定（§5）
- 壁ごとの「あと何円・何時間」
- 月ごとの給与の手入力（総支給、通勤手当、労働時間の3項目で、30秒以内に入力できる）
- 今のペースで超える月の予測
- 通勤手当を自動で振り分ける（税では含めない、社会保険の扶養では含める）
- 残業・深夜の割増を含めた見込み計算（正式な給与計算は行わない）
- 手取りが逆転するゾーンの表示（130万円を超えた場合、どこまで働けば手取りが元に戻るか）
- データは端末内にだけ保存する（アカウント不要）

**原則: 扶養から外れるかどうかの判定そのものは、すべて無料にする。** 安全に関わる判定を有料にすると信頼を失うため。

### 6.2 個人プレミアム（有料）
- 給与明細を撮影して自動で読み取る（§7）
- 年末に向けた逆算（「12月はあと週○時間まで」）
- 通知（ペース超過、壁の手前）
- 複数年の履歴、PDF出力（夫の会社や保険者への説明用）
- 端末間の同期（アカウント作成が必要）

### 6.3 事業所版（主な課金、フェーズ3）
- スタッフ一覧で、社会保険の加入義務（4分の3基準・短時間労働者の要件）を判定する
- スタッフごとの扶養ラインの余裕を一覧にする（本人の同意が前提）
- シフト作成時に「この人はこの時間を入れると超える」と警告する
- 法改正（企業規模要件の縮小など）で影響を受けるスタッフを事前に洗い出す
- 既存の勤怠・給与ソフトからのCSV取り込み
- **事業所が契約すると、スタッフは個人プレミアムが無料になる**（事業所から給与データを連携するので、明細の撮影も不要になる）

## 7. 給与明細の読み取り機能

- **位置づけ**: 個人プレミアムの機能にする。MVPには入れない。
- **有料にする理由**: 読み取りに使う外部APIの費用が1枚ごとにかかる。また、手入力は3項目で済むため、この機能の価値は「手間が省ける」という便利さで、お金を払ってもらいやすい種類の価値だから。
- **必須要件**:
  - 読み取った結果は必ず確認画面に出し、利用者が確認してから保存する（読み間違いで判定を誤らないため）
  - 読み取るのは、支給年月・総支給額・課税支給額・通勤手当・労働時間に限る
  - 画像は、標準設定では保存しない
  - 外部サービスに送ることは、プライバシーポリシーに明記し、使う前に同意を得る
- **技術面**: 明細の書式は事業所ごとにばらばらなので、従来型の文字認識（OCR）よりも、画像を理解できるAIモデルのほうが実用的。スマホアプリ化した後は、端末内の文字認識も選べるようにする。

## 8. 構成（スマホアプリにしやすい作り）

```
packages/
  rules/    年度別のルール表（JSON）。出典・施行日・確認日・監修者つき
  engine/   計算エンジン。画面に依存しない純粋な関数で作り、テストを厚くする
apps/
  web/      Webアプリ（PWA）
  mobile/   後で追加（Capacitorで包む、またはReact Nativeにする）
```

- 言語はTypeScriptに統一し、計算エンジンをWeb・スマホで共有する。
- 個人版は端末内に保存する（IndexedDB）。サーバーに個人の給与データを持たないので、情報漏えいのリスクと法的な負担が小さい。
- 事業所版のみ、サーバー・ログイン・権限管理を持つ。

## 9. デザイン方針

### 9.1 目指すもの
- 余白を広く、情報は1画面に1つの主役だけ。数字（あと何円、あと何時間）を大きく見せる
- 色はモノトーンを基本に、アクセント色を1色だけ使う。状態の色（余裕・注意・超過）は控えめに
- 動きは最小限で、意味のある動きだけにする（画面の切り替え、数字の変化）

### 9.2 使わないもの（AIが作ったように見える要素）
- 紫〜青のグラデーション、光る効果、ガラスのような半透明カードの多用
- 絵文字、「✨」などの装飾記号、見出しの先頭に付けるアイコンの乱用
- 汎用的なWebフォント（Inter、Poppinsなど）のいかにもな使い方
- 「〜しましょう！」「最適化」「シームレス」など、AIの文章によくある言い回し
- カードを3列に並べただけの紹介ページ、意味のないイラスト

### 9.3 文字
- 端末に入っている標準フォントを使う: `-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", sans-serif`
  - iPhoneやMacではAppleの標準フォント（SF・ヒラギノ）で表示されるので、自然にApple製品らしい見た目になる
  - SF Proのフォントファイルを直接配信するのはライセンス上できないので、しない
- 数字は等幅数字（`font-variant-numeric: tabular-nums`）にして、桁がずれないようにする

### 9.4 文章
- 短く、言い切る。ただし判定には必ず確度と根拠を添える
- 専門用語は、初めて出たときに一言で説明する（例: 「被扶養者（夫の保険証に入っている状態）」）

### 9.5 AIの使用について
- 見た目はAIらしくしないが、**明細の読み取りでAIを使うことは隠さない**。外部サービスへのデータ送信は、個人情報保護法上、利用者への説明が必要なため。

## 10. やらないこと（スコープ外）
- 正式な給与計算、年末調整、社会保険の手続き書類の作成・提出
- 個別の税務相談・社労士相談（チャットでの助言を含む）
- 自営業・フリーランスの収入（事業所得）の判定 ※将来検討
