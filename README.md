# threads-affiliate-assistant

Threads × 楽天アフィリエイトの**半自動**運用ツール。
面倒な作業（リサーチ・商品探し・下書き・予約投稿・数値集計）は自動で行い、**投稿してよいかの判断だけは人が承認する**作りです。

```
[毎朝6:00 自動] Threads公式APIで人気投稿を収集 → 楽天APIで商品候補（アフィリンク付き）
      ↓
[自動] Claudeが「親投稿＋コメント欄」の下書きを作成（体験部分は空欄で残す）
      ↓
[人・スマホで1日5〜10分] 承認画面で確認 → 体験を記入 → 「実際に使った」にチェック → 承認
      ↓
[10分ごと 自動] 予約時刻を過ぎた承認済み下書きを投稿（親投稿 → 自分のコメント欄に【PR】＋リンク）
      ↓
[毎晩23:00 自動] 投稿の表示・いいね・返信数を取得
```

## なぜ完全自動にしていないか

- **景品表示法**：使っていない商品の体験談をAIが作ると、PR表記があっても優良誤認のおそれがあります。
  このため下書きには `【ここにあなたの体験】` という空欄が入り、書き換えて「実際に使った」にチェックしないと承認できません。
- **Threadsの規約**：無人の大量投稿や複数アカウントでの同じような投稿は停止リスクがあるため、1日の投稿上限（初期値3件）を設けています。
- **スクレイピングはしない**：収集はすべて公式APIで行います。

## 承認時の自動チェック

| 種類 | 内容 |
|---|---|
| 承認できない（エラー） | 体験の空欄が残っている／「実際に使った」が未チェック／親投稿にリンクがある／文字数が500字を超える（コメントはリンク込み） |
| 警告（人が判断） | 「絶対」「最安」「痩せる」など誇大表現の疑い／参考にした投稿と文章が似すぎている |

コメント欄の投稿には、先頭の `【PR】` と末尾のリンクが自動で付きます。

## セットアップ

### 1. 必要なアカウントとキー

| 用途 | 取得先 | 備考 |
|---|---|---|
| Threads API | Meta for Developers でアプリを作り、Threadsのユースケースを追加 | 権限: `threads_basic` `threads_content_publish` `threads_keyword_search` `threads_manage_insights`。キーワード検索はアプリ審査が必要な場合があります。アクセストークンは長期トークン（60日）に交換し、期限前に更新が必要です |
| 楽天 | 楽天ウェブサービスでアプリIDを発行し、楽天アフィリエイトのアフィリエイトIDを確認 | **楽天アフィリエイトのサイト情報にThreadsアカウントのURLを登録してください**（登録がないと報酬が無効になるおそれがあります） |
| Claude | Claude Console で APIキーを発行 | |

### 2. ローカルで起動（まずはDRY_RUNで）

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # キーを記入。DRY_RUN=true のまま
uvicorn app.web:app --host 0.0.0.0 --port 8000
```

ブラウザで `http://localhost:8000` を開き、`.env` の `APP_USERNAME` / `APP_PASSWORD` でログインします。
画面下の「手動実行」から、収集 → 下書き生成 → 承認 → 予約分を投稿 の流れを試せます（DRY_RUN中は実際には投稿されません）。

ジョブはコマンドでも実行できます: `python -m app.jobs collect|generate|publish|metrics|daily`

### 3. 本番運用

- 常時起動するサーバーと、SQLite用の永続ディスクが必要です（小さなVPS、または永続ディスク付きのRender・Railway・Fly.ioなど）。
- `.env` を `DRY_RUN=false` と `ENABLE_SCHEDULER=true` にします。
- スマホから開くので、**必ずHTTPS経由で公開**し、`APP_PASSWORD` は長く推測されにくいものにしてください。

## 知っておくべき制約

- **他人の投稿の表示回数はAPIで取れません。** 動画にある「1万表示以上」の基準は使えないため、Threadsの人気順（`search_type=TOP`）で代わりにしています。
- **楽天APIの仕様変更に注意。** エラーになったら、`RAKUTEN_SEARCH_URL` と必要なキーを楽天ウェブサービスの公式ドキュメントで確認してください。
- **Claudeの費用。** キーワード1つにつき1日1回の呼び出しで、`claude-opus-5-5` なら1回あたり十数円程度が目安です（キーワード3つで月1,000〜2,000円程度）。費用を下げたいときは `CLAUDE_MODEL` を変更できます（品質との兼ね合い）。
- 親投稿は成功したのにコメントの投稿だけ失敗した場合、下書きは「失敗」に入ります。再承認すると、コメントだけを投稿し直します。

## 開発

```bash
pytest -q
```

構成: `app/threads_client.py`（Threads API）、`app/rakuten_client.py`（楽天API）、`app/generator.py`（Claudeで下書き）、
`app/compliance.py`（承認時チェック）、`app/jobs.py`（定期ジョブ）、`app/web.py` ＋ `app/templates/`（承認画面）、`app/db.py`（SQLite）
