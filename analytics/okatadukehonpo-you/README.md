# okatadukehonpo-you.com 計測設計・実装手順 v1

電話 / LINE / フォームの3導線を GTM + GA4 で計測するための一式です。

| ファイル | 中身 |
|---|---|
| `GTM-container-import.json` | GTMにインポートするコンテナ設定（タグ9・トリガー7・変数5） |
| `src/cta-listener.js` | `tel:` / `mailto:` / LINE リンクのクリック検知（カスタムHTMLタグの中身） |
| `src/form-listener.js` | Contact Form 7 の送信完了・エラー検知（カスタムHTMLタグの中身） |

> `src/` の2ファイルは JSON に埋め込み済みです。中身を直したいときはここを編集して JSON を作り直すか、GTM上で直接編集してください。

---

## 0. 前提の確認（インポート前に必ず）

1. **GA4プロパティの測定ID（`G-` で始まる）** を用意する。
2. **WordPressテーマに直書きされたGA4/gtagタグが無いか確認する。** あるとGTMと二重計測になり、セッション数とCV数が壊れます。
   テーマファイルやSEOプラグイン（All in One SEO / Site Kit 等）の解析設定を検索し、GTM側に一本化してから進めること。
3. **フォームのプラグイン名**を確認する（Contact Form 7 / MW WP Form / Snow Monkey Forms など）。手順5で分岐します。
4. `okatadukehonpo-you-39.com` を同一運営で併用している場合は、クロスドメイン計測の設定要否を先に決める。放置すると同一ユーザーが2セッションに割れ、CVの帰属がずれます。

---

## 1. GTMコンテナへのインポート

> **確認画面の「削除される数」が 0 でなければ、絶対に「ワークスペースに追加」を押さないこと。**
> 1以上なら既存タグが消えます。とくに `コンバージョンリンカー` や広告のコンバージョンタグが消えると、
> Google広告の計測が止まり自動入札の学習がリセットされます。キャンセルして手順4をやり直してください。

1. **先にバックアップ**：管理 → **コンテナのエクスポート**（既存タグがある場合は必須）
2. GTM管理画面 → **管理 → コンテナのインポート** → `GTM-container-import.json` を選択
3. ワークスペース：**新しいワークスペースを選択**（`GA4計測設計v1` など）
4. インポートオプション：**必ず「マージ」**
   - 既存タグがある → 競合の解決は **「名前を変更する」**
   - コンテナが空 → 「競合するタグ、トリガー、変数を上書きする」でよい
   - **「上書き」（コンテナ全体の置き換え）は選ばない。** 既存タグが全削除されます
5. 確認画面で **「削除される数 0」** を確認する
6. 「ワークスペースに追加」。**この時点では公開されません**

万一そのまま追加してしまっても、公開しなければ本番サイトには影響しません。
ワークスペースの変更を破棄するか、バージョン履歴から前のバージョンに戻せます。

### 1-2. 既存の計測タグがある場合（二重計測の回避）

`電話タップ` `LINEクリック` `フォーム送信完了` などが既にあるコンテナでは、マージすると新旧が同時に動きます。
いきなり消さず、次の順で入れ替えてください。

1. 新タグ（`GA4 - tel_tap` など）をプレビューで検証し、正しく発火することを確認
2. 旧タグを**削除ではなく「一時停止」**にする
3. 公開し、GA4のリアルタイムで新イベントが入ることを確認
4. 1週間ほど様子を見て、問題なければ旧タグを削除

**`コンバージョンリンカー` と `広告CV 電話 / LINE / フォーム` のようなGoogle広告用タグは今回の入れ替え対象外。そのまま残すこと。**

インポート直後の確認ポイント：
- GA4イベントタグ（`GA4 - tel_tap` など）の「イベントパラメータ」が入っているか。GTMのバージョン差でパラメータが落ちる場合があるので、落ちていたら手順3の表を見て手入力してください。
- 各GA4イベントタグの「測定ID」が `GT - Google タグ (GA4)` を参照しているか。

## 2. 変数の差し替え（必須）

| 変数名 | 現在の値 | やること |
|---|---|---|
| `CONST - GA4 測定ID` | `G-XXXXXXXXXX` | 実際の測定IDに置換 |
| トリガー `PV - サンクスページ` | `/thanks` を含む | 実際のサンクスページのパスに置換（無ければトリガーごと削除） |

## 3. タグ構成（インポートされるもの）

| タグ名 | イベント名 | 送信パラメータ | 発火条件 |
|---|---|---|---|
| `GT - Google タグ (GA4)` | – | – | 全ページ |
| `cHTML - CTAクリック計測` | – | – | 全ページ |
| `cHTML - フォーム計測 (CF7)` | – | – | 全ページ |
| `GA4 - tel_tap` | `tel_tap` | `click_location` / `service_type` / `value=3000` / `currency=JPY` | `cta_click` かつ `cta_type=tel` |
| `GA4 - line_tap` | `line_tap` | 同上 / `value=1500` | `cta_click` かつ `cta_type=line` |
| `GA4 - mail_tap` | `mail_tap` | 同上 / `value=500` | `cta_click` かつ `cta_type=mail` |
| `GA4 - form_submit` | `form_submit` | `form_id` / `service_type` / `value=2000` | CF7送信完了 **または** サンクスページ表示 |
| `GA4 - form_error` | `form_error` | `form_id` | CF7入力エラー |
| `GA4 - video_start` | `video_start` | `video_title` / `video_url` | YouTube再生開始 |

`value` は導線ごとの受注価値の**相対値**です。実績が出たら「粗利 × 成約率」で更新してください。暫定値のままでも比較には使えます。

`click_location` は次の値を自動判定します：
`fixed_bar`（モバイル追従バー）/ `header` / `fv` / `price` / `case` / `contact` / `footer` / `body`

**判定を確実にしたい箇所は、HTML側でCTAの親要素に `data-cta="fixed_bar"` のように明示してください。** 属性があればそれが最優先されます。テーマを触れる場合はこれが一番壊れません。

## 4. GA4側の設定

### 4-1. キーイベント登録（管理 → イベント → キーイベント）

イベントが1回でも発生しないと一覧に出ません。先に手順6の検証で実際に発火させてから登録するか、「キーイベントを作成」で手入力してください。

| イベント名 | キーイベント |
|---|---|
| `tel_tap` | ✅ |
| `line_tap` | ✅ |
| `form_submit` | ✅ |
| `mail_tap` | ✅ |
| `form_error` / `video_start` | ❌（中間指標のまま） |

キーイベントは1プロパティ30個まで。スクロールや滞在系を足さないこと。広告の自動入札が確実に悪化します。

### 4-2. カスタムディメンション（管理 → データの表示 → カスタム定義）

| ディメンション名 | 範囲 | イベントパラメータ |
|---|---|---|
| CTA設置場所 | イベント | `click_location` |
| サービス種別 | イベント | `service_type` |
| フォームID | イベント | `form_id` |

登録して初めてレポートで分解できます（登録前のデータは遡及しません）。

### 4-3. その他

- **拡張計測機能**：ON のまま。ただし `scroll` `click`（離脱クリック）はキーイベントにしない。
- **データ保持期間**：管理 → データの収集と修正 → データ保持 → **14か月**に変更（初期値2か月）。
- **内部トラフィックの除外**：自社IPを `internal` として定義し、データフィルタを「有効」にする。片付け業は自社スマホからの閲覧が多く、放置するとCVが水増しされます。
- **Google広告とのリンク**：管理 → サービス間のリンク設定 → Google広告。キーイベントをインポートする際、電話は下記「重要」を参照。

## 5. フォーム計測の分岐

| プラグイン | やること |
|---|---|
| Contact Form 7 | そのまま。`cHTML - フォーム計測 (CF7)` が動きます。トリガー `PV - サンクスページ` は**削除**（二重計上防止） |
| MW WP Form / Snow Monkey Forms（サンクスページあり） | `cHTML - フォーム計測 (CF7)` を**一時停止**し、`PV - サンクスページ` のパスを実URLに変更 |
| Ajax完結でサンクスページなし | 完了メッセージ要素に対する「要素の表示」トリガーを追加（要素のセレクタが必要なのでHTMLを共有ください） |

**送信ボタンのクリックで計測してはいけません。** バリデーションエラーも1件として数えてしまいます。

## 6. 検証手順（公開前に必ず）

1. GTMの**プレビュー**を起動し、実機のスマホでサイトを開く（Tag Assistantの共有URLをスマホで開く）
2. 以下を1つずつ実行し、GTMプレビューとGA4の**DebugView**の両方で確認：
   - モバイル追従バーの電話ボタン → `tel_tap` / `click_location=fixed_bar`
   - ヘッダーの電話ボタン → `tel_tap` / `click_location=header`
   - LINEボタン → `line_tap`
   - フォームを**実送信** → `form_submit` が1回だけ
   - フォームをわざと空欄で送信 → `form_error` が出て `form_submit` が**出ない**こと
   - 電話ボタンを連打 → `tel_tap` が1回しか出ないこと
3. PCでも一通り確認（PCの `tel_tap` はほぼ発生しない想定）
4. 問題なければ GTM を**公開**（バージョン名・説明を残す）

## 7. 重要：これだけは設計として守ること

- **`tel_tap` は「発信」ではなく「タップ」。** 実測で3〜5割は通話に至りません。Google広告を運用しているなら「ウェブサイトの電話番号のコンバージョン」で**通話60秒以上**を成果条件にし、入札はそちらを主軸にしてください。GA4の `tel_tap` は「どのCTAが押されたか」の診断用です。
- **LINEのQRコードは計測できません。** サイト内のLINE導線は必ず `https://lin.ee/xxxx` のリンクにすること。
- **個人情報をGA4に送らない。** 氏名・電話番号・住所・フォーム入力値をパラメータに含めない（本設計では `form_id` のみ送信）。
- **電話番号が画像になっている箇所は `tel:` リンク化する。** 計測以前に機会損失です。
